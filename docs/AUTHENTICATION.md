# Authentication

Fortify provides centralized registration, credentials, password reset and email verification. Passport supplies Authorization Code with S256 PKCE. Open a local portal's sign-in link to initiate a state-bound exchange with CanadaMB. Successful authorization establishes a separate browser session on the local hostname. The exchange consumes the authorization code and immediately revokes the access and refresh tokens after validating the user and local client.

Keep cookie Domain unset. Use Secure and HttpOnly with SameSite=Lax over real TLS. Configure APP_URL to the central hostname and keep Laravel and Passport private keys stable. Run passport:keys once per environment, then run network:sync-sso. Protected local forms send unverified users to CanadaMB to verify their email. A user can sign out everywhere from My account. Password reset also invalidates earlier session versions. Enable SMTP and test real verification and reset email before launch.

Backend gates distinguish members, network administrators and super administrators. Businesses have membership roles for scoped editing. City moderator assignments and full account deletion execution remain pending. Password-confirmed selected account exports are implemented; privacy request intake is staged for reviewed migration. MFA is outside current scope.

## Pass 01 prelaunch acceptance

The published setting **Allow prelaunch test registration** defaults off, including for older settings revisions. From an approved connection, a verified super-admin can open **Admin → Settings**, enable the setting, save the draft and publish it. Use a separate browser profile for the tester. The tester can register only at `canadamb.ca`. A Brandon Create account link opens that form and retains Brandon as the community destination. If registration starts from a Brandon sign-in prompt, keep the same browser and tab to preserve the original intended page.

In the administrator profile, open **Admin → Settings → Review pending test accounts**. Confirm the tester's identity, then verify their specific pending account. This action is limited to accounts created through prelaunch registration. It records the administrator, account ID and time. In the tester profile, use **Check verification**, sign in on CanadaMB, then open a protected Brandon page and follow the Passport redirect. Check that the browser returns to the intended Brandon path and query. Use **Sign out everywhere** on either host, then verify that the other host rejects its old session on the next request. That POST clears the current host's cookie. The other host invalidates its old session server-side on use.

Test at desktop and phone widths in light and dark mode. Check both form labels and errors, the mobile navigation's Create account link, normal Marketplace access, IP denial, and existing PWA installation metadata. Confirm a canceled or expired login offers a safe retry. Open two Brandon sign-in tabs while signed out, submit the first tab, then reload the second sign-in page to resume its own request. Check central `/register` is 404 again after the super-admin publishes the switch off. Existing tester accounts can still sign in. From an unapproved network, verify both hosts return 403 for auth and app pages and still expose only the existing public PWA metadata.

Prelaunch does not send verification or password reset email. Test signed verification and password reset through the automated `Notification::fake()` cases, or use a disposable local instance with controlled mail. The normal mail-enabled flow uses expiring links and generic reset responses for registered and unknown addresses. Keep SMTP and prelaunch settings intact on Hostinger during testing.

## Persistent sign-in

Central password login defaults to remembering the member for 30 days; uncheck Keep me signed in on a shared computer. Completing community PKCE sign-in creates a separate host-only 30-day remember cookie on that community. Normal session lifetime is unchanged. Laravel restores a new session from a valid remember token and the existing Login event records the current session version and hostname. Sign out everywhere and password change/reset rotate the database remember token and invalidate network sessions; prior cookies must not restore access. No external identity provider, shared domain cookie, or hosting configuration change is required. HTTPS/Secure/HttpOnly/SameSite settings remain mandatory on production. Do not confuse persistence with offline caching. Real-device acceptance should include browser restart, session-cookie removal, switching sites and sign out everywhere; users on public computers should sign out when finished.
